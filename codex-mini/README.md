# Mini Codex

Unofficial Windows client built with C#, WPF, and .NET 10. Each account uses an official Codex CLI App Server for sign-in, history, streamed tasks, approvals, and interruption. The latest source adds Steer/Queue/Ask sending, code review, editable message queues, find in chat, draft recovery, idle memory saving, an account overview, and actionable Windows notifications. The composer now styles typed lists, projects support recency and custom ordering, and running tasks show thinking progress during text-stream pauses.

## Build and run

Build on Windows with .NET SDK 10.0.402 from this directory:

```powershell
rtk proxy dotnet build src/MiniCodex/MiniCodex.csproj -c Release
```

Run `src/MiniCodex/bin/Release/net10.0-windows10.0.19041.0/MiniCodex.exe`. Close the earlier Mini Codex app first because only one instance can run. This framework-dependent build requires the .NET 10 Windows Desktop Runtime. The Windows API target includes SDK version 10.0.19041.0 for notification APIs; the minimum declared OS version is Windows 10 build 18362. The project references [Microsoft.Toolkit.Uwp.Notifications 7.1.3](https://www.nuget.org/packages/Microsoft.Toolkit.Uwp.Notifications/7.1.3) for unpackaged WPF toast notifications and [Microsoft.Web.WebView2 1.0.4258.31](https://www.nuget.org/packages/Microsoft.Web.WebView2/1.0.4258.31) for the optional in-app usage/reset browser. Embedded browsing requires the Microsoft Edge WebView2 Runtime; when unavailable, the browser window offers **Open in browser**.

If a build reports MSB3027/MSB3021 and says `MiniCodex.exe` is locked by MiniCodex, use the running app's **Exit** action before rebuilding. Closing one chat window can leave another chat or the account manager open, so the process still holds the executable. Stop active work through the app's prompt before exiting.

## Sign in and run a task

1. Open the rebuilt app and choose **Sign in** below the account name at the top left. Complete Codex's ChatGPT sign-in in the browser. Check that the intended email appears in that account window.
2. If the browser callback cannot complete, cancel the attempt and choose **Device code**. Enter the displayed code on the page that opens. Complete one browser login at a time; different Codex processes can compete for the callback port.
3. Create a project or select it in the tree. The empty chat page offers **+ New chat** for a selected project, and typing or attaching a file creates a local draft automatically. The Codex session starts when you send. A project's **⋯** menu also provides **New chat** and **Manage folders…**.
4. Select a discovered model, effort, and approval mode near the message box. Enter a request and choose **Send**, or press Enter. Shift+Enter inserts a new line or continues the current list. Type `-` or a number (`1` or `1.`), then Space, to start a styled list. Shift+Tab indents a list item or selected items; Tab also indents. Backspace at the start of an item outdents it or removes its marker. Shift+Enter on an empty item ends the list.
5. Watch the streamed messages and command output. **Review** opens pending commands, file permissions, or questions for the originating chat. **Stop** interrupts the selected task and waits for its terminal event.
6. To use another account, choose the account control at the top left, add a profile, open its window, and sign in there.

**Ask me** routes approval prompts to the native review dialog. **Auto approval** selects Codex's `auto_review` reviewer while preserving workspace-write sandboxing; it does not make Mini Codex accept every request or disable managed policy. A server rejection is shown rather than retried with broader permissions. Thread start/resume and turn start send the pinned CLI's `on-request` approval-policy value.

The lightning button beside effort switches between **Standard** (outline, default) and **Fast** (filled blue). It saves the preference per account and applies it to new messages without changing effort. Its tooltip shows the selection and usage cost. Fast depends on model/account availability and consumes more of your limits or credits; see [Codex speed](https://learn.chatgpt.com/docs/agent-configuration/speed). Requests use the pinned App Server's `serviceTierForTurn` (`fast` or `default`), so Standard does not inherit a thread's earlier Fast setting. Selecting Fast enables its feature in the request configuration; Mini Codex does not rewrite the home's config file. Server rejections remain visible and are not retried automatically. This source change has not been built or interactively verified.

Usage and credits come from Codex. While signed in and connected, polling runs every minute when this account has a running task and every ten minutes when idle. Sign-in, task completion, manual refresh, and server updates can update usage sooner. Reset countdowns redraw locally each minute without extra requests. Values remain unavailable if the server does not report them. When Codex reports `rateLimitResetCredits.availableCount`, a clickable reset count appears beside usage, for example `90% · 3h 21m | 20% · 3d 2h | 2 rst`. Zero remains clickable as `0 rst`; an unavailable count is omitted. The same button appears in the account overview and retains cached counts for closed accounts. Numeric credits display one decimal place, for example `12.3 credits remaining`. The usage tooltip contains the account plan, update time, and available reset count when known. See the [official rate-limit fields](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt).

Click the reset count to open the [Codex usage/reset page](https://chatgpt.com/codex/settings/usage) in a dark in-app WebView2 window. Back, Reload, Usage page, and **Open in browser** are available. Each account and Codex home has separate website cookies under `%LOCALAPPDATA%\MiniCodex\browser`; website sign-in is separate from the CLI sign-in. The window shows the intended account so you can use the matching website login. Native sign-in tokens are never passed into the browser. Complete any reset on the website, then close the window to refresh that profile's limits through Codex. Opening the button does not consume a reset. Removing an account or changing its Codex home closes its reset browser; preserved browser folders are not automatically deleted.

The composer shows **Context used / capacity**, for example `82k / 128k`, with exact token counts and the used percentage in its tooltip. Unknown values display `?`; counts come from the latest `tokenUsage.last.totalTokens` and `modelContextWindow` reported by Codex. The small inward-arrow **Compact context** icon starts manual context compaction for an idle, saved, active chat through `thread/compact/start`. The chat shows Compacting and shares its running/Stop state across windows until Codex reports completion. Errors and unknown outcomes remain visible and are not retried automatically. Counts update from Codex rather than assuming how much compaction saved. See the [App Server compaction contract](https://learn.chatgpt.com/docs/app-server).

If Windows sandbox setup is required, use the gear menu's **Set up Windows sandbox…** action and complete Windows' setup prompt. The app does not silently select a weaker sandbox.

Open **gear → Codex instructions…** to edit personal guidance separately for each account. The dark editor loads that account's native `AGENTS.md` from its Codex home; an active non-empty `AGENTS.override.md` is edited instead, with its fallback behavior explained. New chats use native Codex instruction discovery, including repository guidance. Running tasks retain their current instructions. **Save instructions**, **Reload**, and **Cancel** manage edits. Existing UTF-8 files are preserved on open/cancel, conflicting external edits require a reload, and an account-home change prevents saving to the previous home. Saves replace the file atomically. The editor supports up to 1 MiB; Codex's own configured instruction budget still applies. Linked instruction files must be edited at their target in an external editor. This follows the [official personal-instructions setting](https://learn.chatgpt.com/docs/app/settings) and [AGENTS.md discovery rules](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

Controls, chat prose, and the rich composer use the Windows system message font family, style, and weight through dynamic system resources. Text sizes and app zoom remain available; code retains its monospace face and icon glyphs retain their symbol fonts. ## Project folders

Press **Ctrl + backtick** in an account window to open a separate terminal for the selected project. A single-folder project opens directly; multiple folders open a dark folder picker with the primary folder selected. The launcher uses Windows Terminal's default profile, falling back to Windows PowerShell if Terminal is unavailable. Cancel opens nothing. Unavailable folders show an error. The shortcut does not submit a Codex task.

Projects default to **last active** order based on the most recent task start. Opening a project/chat, creating an unsent draft, or steering an existing task keeps the current order. Starting a task, review, or context compaction updates the project's saved activity time. Saved chat history (including archived chats) supplies an initial baseline until a task start is recorded for that project; drafts are excluded, and subsequent history timestamps do not override a recorded start. The clock icon beside the Projects heading is highlighted while this ordering is active. Drag a project header above or below another header to save a custom order; a line shows the drop position, and the clock icon deactivates after the drop. Click the clock icon to restore task-start ordering. The preference and custom order are saved per account and shared across its windows. Search preserves the order of hidden projects.

1. Choose **+ New project**, or the **+** beside Projects.
2. In **Manage folders**, choose **Add folders…**. The native folder picker supports selecting multiple folders.
3. Choose a primary folder and save the project.
4. Reopen the panel through the project's **⋯ → Manage folders…** menu or its folder summary.

Folder changes are staged until **Save project**. Cancel discards them. Duplicate paths, including aliases resolved through Windows directory handles, are not added twice. A project requires at least one folder. Before removing the primary folder, select a replacement. Removing a folder detaches it from the project and does not delete or modify its files.

Every chat uses all project folders as writable roots under Codex's workspace-write policy, with the primary folder as its working directory. Each new turn captures the current folder list. Stop an account's tasks before editing its folders. Tasks can run in overlapping project folders without a shared-folder confirmation. Codex and managed policy still enforce actual access.

Mini Codex tracks files reported by App Server `fileChange` items across all open accounts. While two tasks are active, a reported edit to the same file stops the newer task through `turn/interrupt` and pauses its message queue. The sidebar shows an orange circle with a pause symbol after Codex confirms the task has stopped. The chat shows the conflict and **Continue** / **Cancel**. Continue waits for the blocking task to finish, then starts a new turn in the same conversation using the selected model, effort, speed, and approval mode; it asks Codex to reread the affected files and finish the interrupted work. Accepted continuation allows the saved queue to proceed after successful completion. Cancel dismisses the paused task while preserving file changes, history, drafts, and a paused queue. Pause details survive reopening the account and are shared by its views. An unconfirmed stop or connection loss requires recovery and **Refresh chat** before either action.

Conflict detection is best-effort, based on reported edits rather than a before-write lock. An edit can reach disk before its notification or interruption is handled. Terminal commands, scripts, external clients, and tools without `fileChange` items are not tracked; filesystem aliases such as hard links may also escape detection. Existing edits are never rolled back automatically. This source addition has not been built or tested against a live account. See the [App Server file-change events and interruption contract](https://learn.chatgpt.com/docs/app-server).

The indicator follows the selected chat, hides during text reveal, and stops on task completion, interruption, failure, or an unknown outcome. Each queued task starts its own elapsed time when dispatched.

The chevron immediately to the right of Send opens **Steer / Queue / Ask**, which controls sending while a task is running. Its menu marks the current choice, and its tooltip shows the selected mode. The default **Ask** opens a choice each time Send is pressed. **Steer** adds instructions to the active turn through `turn/steer`, retaining that turn's model, effort, speed, and permissions. Steering waits for a confirmed turn ID and is unavailable during context compaction. **Queue** saves the message for the next turn. ## Find, recovery, and memory saver

**Find** or **Ctrl+F** searches the selected chat's loaded messages, including terminal output, file changes, searches, annotations, and question cards. Enter/Shift+Enter or the arrow buttons navigate matches; Escape closes the bar. Matching activity expands automatically, body text is highlighted, and matching annotation/question cards get an accent border. Search is case-insensitive, counts matches in message source, and stops at 5,000 matches. Use **Load earlier** to include older history within the existing transcript limits; this does not search the entire persisted history on the server.

Draft text, reference metadata, attachment paths, annotation comments, and queued messages are saved separately in `%LOCALAPPDATA%\MiniCodex\drafts.json`, with a `.bak` backup. Saves are debounced by 600 ms and use atomic replacement. Normal window closure and app exit flush changes; an abrupt process exit can lose the most recent debounce interval. Drafts are shared by windows viewing the same chat and restored on startup. This app-owned JSON file contains unencrypted draft content, not account credentials or a copy of Codex's history. Its size limit is 32 MiB. Unreadable or invalid recovery data stops startup without overwriting the file; save failures appear in the chat notice. Removing a chat/account or changing its Codex home also removes the associated recovery entries. Attachment files themselves remain on disk.

After ten minutes without user activity, **memory saver** closes an idle account's App Server while keeping its windows, drafts, and visible transcripts. Running or uncertain work, queued messages, pending approvals/questions, login flows, and pending requests prevent suspension. Before disconnecting, it also checks server-loaded threads and background terminals; an unconfirmed or active state keeps the server open. Inactive transcript buffers are released. The status bar shows **Sleeping · reconnect on use**. Keyboard/mouse input or a new task reconnects; usage polling resumes after connection. No RAM measurements have been run.

## Windows notifications

Task completion, failure, approvals, and questions create Windows notifications. **Open chat** focuses the originating chat. Short approval requests can offer **Allow once** and **Deny** when supported by their decision contract. A single non-secret question with at most five short options can be answered through a selection box or custom answer field and **Submit answer**. Longer, multiple, or secret questions and complex approval scopes open the full in-app review dialog. Notification actions validate the live request and connection; stale notifications can open a chat but cannot approve or answer a newer request.

The notification toolkit handles unpackaged WPF registration. Windows notification settings and registration must allow delivery; failures that raise an error appear in the app notice. Notification activation and action handling have not been verified on this machine. The in-app review controls remain available if notifications are unavailable.

**Usage limits reset** notifications identify the account and which quota window reset, with the newly reported remaining percentage. **Open account** focuses that profile. Only confirmed changes in usage limits notify; new earned reset credits do not. Initial snapshots and reconnect/sign-in baselines stay silent. Repeated polling or duplicate server updates do not repeat the same alert, and simultaneous short-term/weekly resets share one notification. A countdown reaching zero schedules a check rather than assuming a reset happened.

While Mini Codex is running, a background scheduler covers all registered signed-in accounts, including profiles whose windows are closed or sleeping. It checks locally each minute and fetches usage about every ten minutes, sooner around a reported reset time; a still-unconfirmed expired window is checked again in about a minute. Closed-account servers are released after the read. Background checks do not count as user activity, and previously sleeping accounts return to memory saver when still idle. Known signed-out profiles resume monitoring after sign-in or an explicit account refresh. Network failures back off for ten minutes. Exiting the app stops monitoring; reopening establishes fresh, silent baselines.

Preview reads the name/description and pins the resolved commit; **Install** downloads a repository archive and installs only the selected skill folder into `<selected CODEX_HOME>/skills/<folder-name>`. It requires readable `SKILL.md` metadata, refuses to overwrite an existing destination, and does not run bundled scripts during installation. Public HTTPS GitHub repositories are supported; private repositories and Git authentication are outside this flow. Download and extraction limits reject oversized or unsafe archives. Install is available when the account has no active work or pending sign-in. During installation, sending, review, compaction, sign-out, reconnect, and closing the account's last window are blocked. Another view of the same account can still close. Installation refreshes the catalog and App Server discovery; start a new chat or reconnect when a newly installed extension is not exposed yet. An uncertain plugin install result requires a catalog refresh before another install. No package is installed merely by browsing or previewing. This source addition has not been built or exercised against a live marketplace or account.

Type **/** in the composer to find skills, or **@** to find files, folders, plugins, skills, and connectors. Use the arrow keys and **Enter** or **Tab**, or click a suggestion; **Escape** dismisses the picker. File suggestions can appear while capabilities are still loading. Autocomplete shows up to 40 suggestions and scans at most 6,000 filesystem entries, to a depth of 20. It skips `.git`, `node_modules`, `bin`, and `obj` subtrees during autocomplete; the file explorer can still browse those folders. Use the explorer when a file does not appear in suggestions.

The native rich composer displays references as short colored chips, preserving their Markdown markers and full targets in the outgoing request. Plugin/skill descriptions appear on hover (plugin summaries may be derived from their discovered skills); Ctrl+click opens file/folder mentions. Full paths stay in tooltips. Reference metadata is saved with that chat's recoverable draft. Removing a marker stops sending its structured reference, and undoing the edit restores it. Sending successfully clears the submitted draft and its references unless the draft changed while submission was pending. ## Annotations and attachments

Select reply text or text inside a code panel to show a floating **Annotate** button near the selection. It appears after the mouse is released or text is selected with the keyboard. Click it to attach the quote and focus its comment field. Clearing the selection, scrolling, changing chats, leaving the window, or pressing Escape closes the button. The right-click **Annotate selection** action is also available. Each quote gets its own comment field. Add further quotes/comments and press **Send** to submit all pairs with any general message. Sent annotations use separate quote/comment cards and retain that presentation when their message is reloaded. Hover for the full excerpt; **×** removes a draft annotation. Older quote-only messages remain supported. The combined serialized quote/comment block is limited to 65,536 characters so it fits within transcript retention.

Use **Attach**, drag files onto the composer, or paste files/images from the clipboard. Draft cards include names, image thumbnails, Open, and Remove. Sent cards remain in user messages and loaded history. Images use App Server `localImage` input; ordinary files are referenced by absolute path in the request. Local file access still follows Codex's sandbox and approval policy. Up to 20 attachments are allowed per message; images must be 25 MB or smaller. Clipboard images are saved under `%LOCALAPPDATA%\MiniCodex\attachments` so the CLI can read them and history can reopen them. They are not automatically removed.

All application confirmation and error dialogs use the dark theme. Native Windows file/folder pickers follow Windows appearance. The ICO export removes excess transparent padding to increase its visible taskbar size.

## Storage and current limits

App-owned state is stored at `%LOCALAPPDATA%\MiniCodex\ui-state.json`, with a last-saved backup at `ui-state.json.bak`. Saves use a temporary file and atomic replacement before publishing the new state to windows. Unreadable settings and unknown schema versions stop startup without overwriting the original file.

**Ctrl+Plus** (including Ctrl+=) and **Ctrl+Minus** scale the app's text, controls, and spacing in 5-point percentage steps, from 75% to 150%. Numeric keypad plus/minus also work. Zoom is shared across app windows, dialogs, menus, and popups and saved across restarts. Native Windows file/folder pickers retain Windows scaling.

New isolated profiles have an immutable home at `%LOCALAPPDATA%\MiniCodex\profiles\<profile-id>\codex-home`. The launcher canonicalizes that home, sets both Codex home and SQLite storage scope, removes inherited authentication/provider overrides, and requests Codex-managed `keyring` storage with no application fallback to plaintext. Connected existing homes retain their storage policies. Codex owns credentials, transcripts, indexes, and databases. Mini Codex does not copy tokens or edit those private files. Login URLs and device codes stay in memory.

Messages use native WPF Markdown rendering with selectable body text, headings, emphasis, lists, block quotes, tables, inline code, and fenced code panels. Replies remain intact; simplification affects presentation and does not add shorter-response instructions. Colors distinguish headings, code, file links, successful status updates, and warnings. User messages start directly with their content, without a reserved sender-header row. Message copy icons appear on hover or keyboard focus and preserve the original source. User-message copy icons sit beside the content. Activity and code panels use the same copy icon, with tooltips and accessible labels.

Terminal output, file changes, and searches start collapsed. Adjacent activity items share one expandable block; its expansion state survives streaming updates and is shared by open views. Activity blocks collapse in all views when the task completes, fails, or is interrupted, and can be reopened afterward. Manual context compaction leaves their expansion state alone. Code examples stay expanded. Changed files display filename links with full paths in tooltips, Open, and Show in Explorer. Relative paths resolve against the chat's working directory. Scrolling up stops automatic following; scrolling to the bottom resumes it. Nested code panels consume wheel input while they have room, then pass it to the conversation. **Load earlier** anchors the currently visible message and adjusts after Markdown layout settles; scrolling or changing chats cancels that adjustment. The existing transcript retention limits still apply.

HTML and arbitrary remote image embedding are disabled. File/image attachments use native cards and local thumbnails. The Markdown renderer supports basic formatting, with plain text after its formatting budget is reached. Visible live Codex replies reveal Unicode text elements on a 16 ms timer, draining larger chunks faster. Completed paragraphs retain Markdown formatting; the unfinished block uses plain text until it closes or the reply completes. This avoids rebuilding Markdown per character. Historical messages appear immediately, other content updates retain 150 ms batching, and collapsed activity skips rendering. Animations stop while hidden/unloaded and respect Windows' client-area animation setting. The renderer uses native WPF controls without a browser. These source changes have not been built or interactively verified.

Display retention is capped at 500 items and 2,097,152 characters per cached conversation. Each profile retains up to six idle conversation states plus active tasks and conversations visible in open windows. Individual messages are truncated at 131,072 characters. Full persisted history stays with Codex. Windows Job Object crash cleanup, automated compatibility checks, and measured memory/startup results remain outstanding. Existing-home compatibility needs live verification with the pinned CLI.

Two-account credential isolation and Windows tool execution still require live verification.
