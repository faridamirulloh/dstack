# Code Archaeology

Use repository history only when Git inspection is explicitly authorized and allowed by local instructions.

Trace the target file or symbol through renames, additions and removals, blame around the relevant lines, substantive change diffs, co-changed files, and linked review or issue references. Read commit messages as leads, not proof. Tests, ADRs, and documentation near the change often state constraints more reliably.

Record the exact revision, path, date, author when relevant, and a short excerpt within citation limits. Distinguish "introduced together" from "introduced because of". Squashes, backports, bot changes, copied patterns, and missing review history all lower confidence.
