# Issue and Ticket Trackers

Use any issue tracker available through current tools or user-provided links.

Start with IDs linked from code, reviews, commits, or documentation. Then search by feature name, domain term, symbol, error text, team, and the dates around the change. Follow parent issues, duplicates, related incidents, and decision comments.

Prefer explicit problem statements, acceptance criteria, and recorded decisions over labels or status. Cite the item and comment or section. A ticket describing work is evidence of intent; it is not proof that the implementation achieved it.
